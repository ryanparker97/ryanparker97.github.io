[Phần 1](/vi/blog/neovim-setup-1-zero-to-editor/) đã cho bạn một trình soạn thảo chạy được. Phần này giúp từng loại tệp được hiểu đúng nghĩa: Python, Lua, tệp web, Bash, Terraform, YAML, Docker, Markdown và TOML đều có language server và gợi ý mã, cùng với trình định dạng và linter phù hợp.

Đây là bốn công cụ riêng biệt, và đó là chủ ý. Language server hiểu mã. Gợi ý mã đưa hiểu biết đó đến bạn khi bạn gõ. Trình định dạng viết lại tệp khi bạn lưu. Linter chạy thêm các bước kiểm tra bằng dòng lệnh. Khi một trong số đó hỏng, bạn biết nên tìm ở đâu, thay vì lục lọi trong một plugin khổng lồ. Bạn có thể xem cả chuỗi bài trên [trang chuỗi bài viết](/vi/blog/series/neovim-setup-guide/).

<Callout type="note" lang="vi">
  **Đã thử với:** Neovim 0.12, macOS.
</Callout>

## Bạn sẽ có gì khi kết thúc

Khi xong phần này, bạn sẽ đã tạo bốn tệp plugin và một phần bổ sung nhỏ cho `autocmds.lua`, và cấu hình sẽ cho bạn:

- **16 language server** do Mason cài, được cấu hình bằng `vim.lsp.config` có sẵn của Neovim và khởi chạy bằng `vim.lsp.enable` (Java được khởi chạy riêng, ở Phần 4).
- Gợi ý mã bằng **blink.cmp**, kèm tài liệu và gợi ý chữ ký hàm.
- **Định dạng khi lưu**, với trình định dạng chọn theo từng loại tệp.
- **Linter** chỉ chạy khi đã được cài, và bỏ qua các linter chậm khi bạn đang gõ.
- **Chẩn đoán** ngay trên dòng hiện tại, với một cửa sổ nổi khi bạn nhảy giữa các chẩn đoán.
- Một **công thức để thêm ngôn ngữ của riêng bạn**.

## Trước khi bắt đầu

Hãy hoàn thành [Phần 1](/vi/blog/neovim-setup-1-zero-to-editor/) trước, để bạn có thư mục cấu hình và mọi tệp của phần đó, và `:checkhealth lazy` không báo lỗi. Mọi đường dẫn trong phần này đều tính từ cùng thư mục cấu hình. Nếu ở Phần 1 bạn chọn cách tạo song song với cấu hình cũ, hãy khởi động Neovim bằng `NVIM_APPNAME=nvim-guide nvim`.

Mason tự cài hầu hết công cụ trong phần này. Các bản Homebrew của `terraform`, `shellcheck`, `shfmt`, `tflint` và `cfn-lint` từ Phần 1 là tùy chọn, vì Mason cũng cài chúng. Node vẫn phải lấy từ Homebrew, vì nhiều server và `prettier` chạy trên nó.

## Các mảnh ghép khớp nhau thế nào

| Plugin | Nạp khi | Nhiệm vụ |
| --- | --- | --- |
| mason.nvim | lệnh `:Mason` | cài server và công cụ |
| mason-tool-installer | `VeryLazy` | cài các trình định dạng và linter |
| nvim-lspconfig + mason-lspconfig | `BufReadPre` / `BufNewFile` | cấu hình và khởi chạy các server |

| nvim-lint | `BufReadPost` / `BufNewFile` | linting |

## Bước 1: tạo lsp.lua

Tệp này chứa Mason, các language server và thiết lập chẩn đoán. Đây là tệp dài nhất của phần này, nên bạn tạo nó một lượt rồi đọc giải thích sau.

1. Tạo `lua/config/plugins/lsp.lua` với nội dung sau:

   ```lua title="lua/config/plugins/lsp.lua" {88,124,152,209}
   local python_310 -- cached result of has_python_310()

   -- Spawns python3 once, on first call; only invoked when mason-tool-installer loads.
   local function has_python_310()
     if python_310 ~= nil then
       return python_310
     end
     python_310 = false
     if vim.fn.executable("python3") == 0 then
       return python_310
     end
     local version = vim.fn.system({
       "python3",
       "-c",
       "import sys; print(f'{sys.version_info.major}.{sys.version_info.minor}')",
     })
     if vim.v.shell_error ~= 0 then
       return python_310
     end
     local major, minor = version:match("^(%d+)%.(%d+)")
     major, minor = tonumber(major), tonumber(minor)
     python_310 = (major and minor and (major > 3 or (major == 3 and minor >= 10))) and true or false
     return python_310
   end

   local function mason_tools()
     local tools = {
       "stylua",
       "prettier",
       "shfmt",
       "shellcheck",
       "eslint_d",
       "hadolint",
       "tflint",
       "cfn-lint",
       "ruff",

       "java-test",

       "yamllint",
       "actionlint",

       vim.list_extend(tools, { "sqlfluff" })
     end

   end

     "lua_ls",
     "basedpyright",
     "ruff",
     "vtsls",
     "html",
     "cssls",
     "tailwindcss",
     "emmet_ls",

     },

         return { ensure_installed = mason_tools(), run_on_start = true }

         -- by the time a VeryLazy load happens.
         installer.run_on_start()
       end,
     },

     {

       dependencies = {
         "mason-org/mason.nvim",
         "mason-org/mason-lspconfig.nvim",

       },
       init = function()

         vim.diagnostic.config({
           underline = true,
           virtual_text = { current_line = true },
           severity_sort = true,

             on_jump = function(_, bufnr)
               vim.diagnostic.open_float({ bufnr = bufnr, scope = "cursor", focus = false })
             end,

       config = function()
         local capabilities = require("blink.cmp").get_lsp_capabilities()
         vim.lsp.config("*", { capabilities = capabilities })

         vim.api.nvim_create_autocmd("LspAttach", {
           group = vim.api.nvim_create_augroup("user_lsp_attach", { clear = true }),
           callback = function(event)
             local client = vim.lsp.get_client_by_id(event.data.client_id)
             if client and client.name == "ruff" then
               client.server_capabilities.hoverProvider = false
             end
             local function map(mode, lhs, rhs, desc)
               vim.keymap.set(mode, lhs, rhs, { buffer = event.buf, desc = "LSP: " .. desc })
             end
             -- Built-ins (0.11+): K hover, grr references, gri implementation,
             -- grn rename, gra code action, gO document symbols.
             map("n", "gd", vim.lsp.buf.definition, "Definition")
             map("n", "gD", vim.lsp.buf.declaration, "Declaration")
             map({ "n", "x" }, "<leader>ca", vim.lsp.buf.code_action, "Code action")
           end,

         vim.lsp.config("lua_ls", {

       end,
     },

     { "b0o/schemastore.nvim", lazy = true },
   ```

### Mason cài các công cụ

Mason tải server, trình định dạng và linter về thư mục riêng của nó. Hàm `mason_tools()` ở đầu tệp dựng danh sách công cụ, và bảng `lsp_servers` bên dưới liệt kê 16 server.

`sqlfluff` chỉ được thêm trên Python 3.10 trở lên. Một hàm hỗ trợ tên `has_python_310()` chạy `python3` một lần, vào lần dùng đầu tiên, và nhớ kết quả. Nhờ vậy một lần cài chắc chắn thất bại sẽ không bao giờ được thử.

Spec `mason-tool-installer` cài danh sách công cụ đó. Dòng `installer.run_on_start()` được tô sáng đã được giải thích bằng chú thích phía trên nó: plugin bắt đầu cài khi có `VimEnter`, nhưng cấu hình này nạp nó muộn hơn, ở `VeryLazy`, nên `config` gọi `run_on_start()` bằng tay.

Ba lệnh đáng biết: `:Mason` mở cửa sổ cài đặt, `:MasonToolsInstall` cài những gì còn thiếu trong danh sách, và `:checkhealth mason` kiểm tra bản thân Mason có chạy được không.

### Server với API có sẵn

Từ Neovim 0.11, bạn không cần plugin để cấu hình server. Bạn mô tả một server bằng `vim.lsp.config` và khởi chạy nó bằng `vim.lsp.enable`. nvim-lspconfig vẫn cung cấp các thiết lập mặc định cho từng server, và mason-lspconfig gọi `vim.lsp.enable` cho mọi server nó đã cài, trừ `jdtls`, thứ mà Phần 4 tự xử lý. Đó là dòng `automatic_enable` được tô sáng gần cuối tệp. Nó bật mọi gói đã cài mà cũng dùng được như language server, nên `tflint` và `stylua` cũng hiện ra như các client.

Trong `config`, dòng đầu tiên đặt thiết lập dùng chung cho mọi server: `vim.lsp.config("*", …)` cho tất cả biết rằng gợi ý mã đến từ blink.cmp. Hầu hết server không cần gì thêm; một vài server có phần ghi đè ngắn.

Python có hai server, và chúng chia việc: basedpyright lo kiểu dữ liệu và hover, ruff lo import và định dạng. Vì vậy hai thứ được tắt đi, và cả hai đều được tô sáng: hover của ruff, trong một handler `LspAttach`, và organize-imports của basedpyright. Thiếu một trong hai, bạn sẽ gặp hover bị lặp và hai công cụ tranh nhau thứ tự import.

Các phần ghi đè khác đều nhỏ. lua_ls dùng runtime LuaJIT với các tệp runtime của Neovim làm thư viện, và lazydev thêm các kiểu của `vim.uv`. emmet_ls bị giới hạn ở các tệp markup, và terraformls gắn vào `terraform`, `terraform-vars` và `hcl`. jsonls và yamlls đọc schema từ SchemaStore; chi tiết về YAML được bàn ở Phần 3.

Ba phím tắt đến từ tệp này, được thêm trong cùng handler `LspAttach`. Một hàm hỗ trợ cục bộ nhỏ `map()` bọc `vim.keymap.set`, làm mỗi phím chỉ có hiệu lực trong buffer và thêm tiền tố "LSP: " vào mô tả. Các phím là `gd` (định nghĩa), `gD` (khai báo) và `<leader>ca` (code action). Chúng chỉ có hiệu lực trong buffer, nên không tồn tại trong các tệp không có server. Những phím như `K` và `grn` đã có sẵn trong Neovim, nên cấu hình để yên chúng.

### Chẩn đoán

Lời gọi `vim.diagnostic.config` nằm trong `init` của plugin, nên nó có hiệu lực trước khi bất kỳ client nào gắn vào. Từng phần làm gì:

- `virtual_text = { current_line = true }` hiện thông báo ở cuối dòng, chỉ cho dòng con trỏ của bạn đang đứng.
- `severity_sort` xếp lỗi trước cảnh báo.
- `on_jump` mở một cửa sổ nổi với thông báo đầy đủ khi bạn nhấn `]d` hoặc `[d`.
- `source = true` ghi tên công cụ đã báo vấn đề.

<Callout type="note" lang="vi">
  Các hướng dẫn cũ dùng `jump = { float = true }`. Tùy chọn đó đã lỗi thời (deprecated), nên cấu hình
  của bạn tự mở cửa sổ nổi bằng `on_jump`.
</Callout>

## Bước 2: gợi ý mã với blink.cmp

blink.cmp là menu gợi ý mã.

1. Tạo `lua/config/plugins/completion.lua` với nội dung sau:

   ```lua title="lua/config/plugins/completion.lua" {4,8,11,18}
   return {
     {
       "saghen/blink.cmp",
       version = "1.*",
       event = "InsertEnter",
       dependencies = { "rafamadriz/friendly-snippets" },
       opts = {
         keymap = { preset = "enter" },
         signature = { enabled = true },
         appearance = { nerd_font_variant = "mono" },
         completion = { documentation = { auto_show = true, auto_show_delay_ms = 500 } },
         sources = {
           default = { "lsp", "path", "snippets", "buffer" },
           per_filetype = {
             lua = { inherit_defaults = true, "lazydev" },
           },
           providers = {
             lazydev = { name = "LazyDev", module = "lazydev.integrations.blink", score_offset = 100 },
           },
         },
       },
     },
   }
   ```

2. Lưu tệp.

Đây là bản ngắn. Phần 3 thay cả tệp bằng một bản dài hơn có thêm gợi ý mã cho cơ sở dữ liệu, nên đừng lo vì nó trông nhỏ.

Spec được ghim ở `version = "1.*"`, nên một bản cập nhật không thể nhảy sang phiên bản major mới. Preset `enter` nghĩa là <kbd>Enter</kbd> chấp nhận mục đang được chọn. Gợi ý chữ ký hàm được bật, và tài liệu hiện ra sau 500 ms. Gợi ý đến từ language server, đường dẫn tệp, snippet và các từ trong buffer, và trong tệp Lua thì lazydev đứng đầu nhờ `score_offset` bằng 100.

Ở chế độ insert, `<C-s>` là gợi ý chữ ký hàm có sẵn.

## Bước 3: định dạng khi lưu với conform

conform.nvim chạy một trình định dạng khi bạn lưu. Nó chọn trình định dạng theo loại tệp.

1. Tạo `lua/config/plugins/formatting.lua` với nội dung sau:

   ```lua title="lua/config/plugins/formatting.lua" {17,18}
   return {
     {
       "stevearc/conform.nvim",
       event = { "BufWritePre" },
       cmd = { "ConformInfo" },
       keys = {
         {
           "<leader>cf",
           function()
             require("conform").format({ async = true, lsp_format = "fallback" })
           end,
           mode = { "n", "v" },
           desc = "Format",
         },
       },
       opts = {
         notify_on_error = false,
         format_on_save = { timeout_ms = 1500, lsp_format = "fallback" },
         formatters_by_ft = {
           lua = { "stylua" },
           python = { "ruff_organize_imports", "ruff_format" },
           javascript = { "prettier" },
           javascriptreact = { "prettier" },
           typescript = { "prettier" },
           typescriptreact = { "prettier" },
           html = { "prettier" },
           css = { "prettier" },
           json = { "prettier" },
           jsonc = { "prettier" },
           yaml = { "prettier" },
           ["yaml.cloudformation"] = { "prettier" },
           markdown = { "prettier" },
           sh = { "shfmt" },
           bash = { "shfmt" },
           sql = { "sqlfluff" },
           ["sql.dbt"] = { "sqlfluff" },
           dbt = { "sqlfluff" },
           terraform = { "terraform_fmt" },
           ["terraform-vars"] = { "terraform_fmt" },
           hcl = { "terraform_fmt" },
         },
       },
     },
   }
   ```

2. Lưu tệp.

`timeout_ms = 1500` ngăn một trình định dạng chậm làm treo lần lưu. `lsp_format = "fallback"` xử lý các loại tệp không có mục riêng, như Java, TOML và Dockerfile: nếu language server của chúng định dạng được thì nó sẽ làm. Python chạy hai bước, sắp xếp import rồi định dạng, đều từ ruff. Các loại tệp web và Markdown dùng `prettier`. Các mục `sql`, `sql.dbt` và `dbt` dùng `sqlfluff`, thứ mà Phần 3 sẽ đưa vào sử dụng.

`notify_on_error = false` giữ cho lỗi im lặng. Như vậy yên tĩnh, nhưng một trình định dạng hỏng sẽ không báo cho bạn, nên hãy chạy `:ConformInfo` để xem chuyện gì đã xảy ra.

`<leader>cf` định dạng buffer bằng tay, ở chế độ normal và visual, nên bạn có thể chỉ định dạng phần đang chọn. Nó chạy bất đồng bộ, nên trình soạn thảo không bao giờ phải chờ.

## Bước 4: linting với nvim-lint

Linter chạy một công cụ dòng lệnh và biến kết quả của nó thành chẩn đoán.

1. Tạo `lua/config/plugins/linting.lua` với nội dung sau:

   ```lua title="lua/config/plugins/linting.lua" {28,57,68,79}
   return {
     {
       "mfussenegger/nvim-lint",
       event = { "BufReadPost", "BufNewFile" },
       dependencies = { "mason-org/mason.nvim" },
       config = function()
         local lint = require("lint")
         lint.linters_by_ft = {
           javascript = { "eslint_d" },
           javascriptreact = { "eslint_d" },
           typescript = { "eslint_d" },
           typescriptreact = { "eslint_d" },
           sh = { "shellcheck" },
           bash = { "shellcheck" },
           dockerfile = { "hadolint" },
           sql = { "sqlfluff" },
           ["sql.dbt"] = { "sqlfluff" },
           dbt = { "sqlfluff" },
           terraform = { "tflint" },
           ["terraform-vars"] = { "tflint" },
           hcl = { "tflint" },
           markdown = { "markdownlint-cli2" },
           yaml = { "yamllint" },
           ["yaml.cloudformation"] = { "cfn_lint" },
         }

         -- Slow linters: never run while typing (InsertLeave).
         local slow = { sqlfluff = true }

         -- Per-linter availability cache: only hits are cached, so tools installed mid-session are picked up.
         local availability = {}

         local function resolve_linter(name)
           local linter = lint.linters[name]
           if type(linter) == "function" then
             local ok, resolved = pcall(linter)
             if not ok then
               return nil
             end
             linter = resolved
           end
           return linter
         end

         local function linter_is_available(name)
           if availability[name] then
             return true
           end
           local available = false
           local linter = resolve_linter(name)
           if linter then
             local cmd = linter.cmd
             if type(cmd) == "function" then
               local ok, resolved = pcall(cmd)
               cmd = ok and resolved or nil
             end
             available = type(cmd) == "string" and vim.fn.executable(cmd) == 1
           end
           if available then
             availability[name] = true
           end
           return available
         end

         local function linters_for(bufnr)
           local ft = vim.bo[bufnr].filetype
           if ft == "yaml" and vim.api.nvim_buf_get_name(bufnr):find("/%.github/workflows/") then
             return { "actionlint" }
           end
           return lint.linters_by_ft[ft]
         end

         local function try_lint(bufnr, opts)
           local names = linters_for(bufnr)
           if not names then
             return
           end
           local available = vim.tbl_filter(function(name)
             if opts and opts.skip_slow and slow[name] then
               return false
             end
             return linter_is_available(name)
           end, names)
           if vim.tbl_isempty(available) then
             return
           end
           lint.try_lint(available)
         end

         local group = vim.api.nvim_create_augroup("nvim_lint", { clear = true })
         vim.api.nvim_create_autocmd({ "BufWritePost", "BufReadPost" }, {
           group = group,
           callback = function(args)
             try_lint(args.buf)
           end,
         })
         vim.api.nvim_create_autocmd("InsertLeave", {
           group = group,
           callback = function(args)
             try_lint(args.buf, { skip_slow = true })
           end,
         })
       end,
     },
   }
   ```

2. Lưu tệp.

Bảng `linters_by_ft` ở đầu tệp ánh xạ loại tệp sang các linter của nó. Tệp này bổ sung thêm ba quy tắc, và các dòng được tô sáng cho thấy từng quy tắc.

**Chỉ linter đã cài mới chạy.** Cấu hình kiểm tra lệnh của linter có tồn tại trên máy bạn không (dòng `vim.fn.executable`). Chỉ các lần kiểm tra thành công mới được nhớ, nên công cụ bạn cài giữa phiên sẽ được tìm thấy ở lần sau.

**Linter chậm bỏ qua `InsertLeave`.** Linting chạy khi lưu, khi mở và khi bạn rời chế độ insert. Các công cụ chậm sẽ làm trường hợp cuối này ì ạch, nên bảng `slow` đánh dấu chúng và phép kiểm tra `skip_slow` bỏ chúng ra ở đó.

**Workflow dùng actionlint.** YAML dưới `.github/workflows/` là tệp GitHub Actions, nên `linters_for()` trả về `actionlint` cho nó thay vì `yamllint`.

Plugin phụ thuộc vào mason.nvim, nên thư mục `bin` của Mason nằm trong `PATH` trước lần lint đầu tiên. Đây là bức tranh đầy đủ, theo từng ngôn ngữ:

| Ngôn ngữ | Server | Định dạng | Lint |
| --- | --- | --- | --- |
| Python | `basedpyright` + `ruff` | `ruff` | chẩn đoán của `ruff` |
| Lua | `lua_ls` + lazydev | `stylua` | không có |
| Web/JSON | `vtsls`, `html`, `cssls`, `tailwindcss`, `emmet_ls`, `jsonls` | `prettier` | `eslint_d` |
| Bash | `bashls` | `shfmt` | `shellcheck` |
| Terraform/HCL | `terraformls` | `terraform fmt` | `tflint` |
| YAML | `yamlls` + SchemaStore | `prettier` | `yamllint` |
| GitHub Actions | `yamlls` | `prettier` | `actionlint` |
| Docker | `dockerls` | không có | `hadolint` |
| Markdown | `marksman` | `prettier` | `markdownlint-cli2` |
| TOML | `taplo` | taplo, qua phương án dự phòng của LSP | không có |

dbt/SQL và CloudFormation nằm ở Phần 3, Java ở Phần 4.

## Bước 5: sửa loại tệp .tf

Đôi khi Neovim đoán sai loại tệp. Các tệp `.tf` mới và trống bị nhận là `tf`, nên trình định dạng Terraform và language server sẽ bỏ sót chúng cho đến khi bạn mở lại tệp. Một ánh xạ nhỏ sẽ sửa điều đó.

1. Mở `lua/config/core/autocmds.lua`, tệp bạn đã tạo ở Phần 1.
2. Thêm các dòng sau vào ngay đầu tệp, phía trên `local augroup = …`, và để một dòng trống giữa chúng với dòng đó:

   ```lua title="lua/config/core/autocmds.lua"
   -- Filetype hints for SRE/data files that Neovim cannot always infer.
   vim.filetype.add({
     extension = {
       -- Built-in detection returns "tf" for empty or comment-only files, so new
       -- Terraform buffers would miss the terraform formatters/LSP until reopened.
       tf = "terraform",
     },
   })
   ```

3. Lưu tệp.

Đây là phần đầu của một lời gọi `vim.filetype.add`. Phần 3 sẽ thêm các quy tắc nhận diện khác vào đó.

## Bước 6: cài đặt mọi thứ

1. Thoát Neovim rồi khởi động lại. lazy.nvim tự cài các plugin mới. Chờ đến khi `:Lazy` không còn mục nào đang chờ cài.
2. Mở một tệp bất kỳ, ví dụ `nvim hello.py`. Việc này nạp nvim-lspconfig, và mason-lspconfig bắt đầu cài các server. Vài giây sau, mason-tool-installer bắt đầu cài các trình định dạng và linter.
3. Chạy `:Mason` để theo dõi các lượt tải. Các công cụ Java khá lớn, nên lần cài đầu có thể mất vài phút.
4. Khi `:Mason` không còn lượt cài nào đang chạy, hãy chạy `:MasonToolsInstall` một lần. Lệnh này cài mọi thứ trong danh sách mà còn thiếu, và không làm gì nếu đã đủ.

Bạn sẽ thấy các công cụ đã cài được liệt kê trong `:Mason`. Hãy khởi động lại Neovim thêm một lần để các server chạy khi đã có đủ công cụ.

## Bước 7: kiểm tra mọi thứ hoạt động

Trước hết kiểm tra Python, thứ dùng nhiều mảnh ghép nhất cùng lúc.

1. Tạo một thư mục và một tệp có vài dòng mã chưa gọn:

   ```sh
   $ mkdir -p ~/lsp-test && cd ~/lsp-test
   $ nvim hello.py
   ```

2. Gõ đoạn sau vào tệp:

   ```python
   import sys,os
   def greet(name):
       return "hello " + name
   x=greet("world")
   print(x)
   ```

3. Chờ một hai giây. Thanh trạng thái liệt kê `basedpyright` và `ruff`, và ruff cảnh báo ở dòng import.
4. Đặt con trỏ lên `greet` rồi nhấn <kbd>K</kbd>. basedpyright hiện chữ ký của hàm.
5. Ở một dòng mới, gõ `prin`. Menu gợi ý mã đề xuất `print`.
6. Lưu bằng `:w`. Tệp được viết lại: các import được sắp xếp thành hai dòng, `x = greet("world")` có đủ khoảng trắng, và hai dòng trống xuất hiện trước `def`. Chạy `:ConformInfo` và bạn thấy `ruff_organize_imports` và `ruff_format`.

Rồi thử thêm ba tệp nữa:

- `nvim main.tf`: thanh trạng thái liệt kê `terraformls`. Lưu bằng `:w`, và `:ConformInfo` hiện `terraform_fmt`.
- `nvim test.sh`: bắt đầu tệp bằng `#!/usr/bin/env bash`, thêm `echo $1` rồi lưu. shellcheck thường sẽ hiện một ghi chú về việc đặt biến trong dấu nháy.
- `nvim package.json`: thêm một khóa, và gợi ý mã đề xuất các khóa đã biết, từ SchemaStore.

Cuối cùng, chạy `:checkhealth vim.lsp` để xem báo cáo về language server.

<Callout type="tip" lang="vi">
  `:LspInfo` chỉ là bí danh của `:checkhealth vim.lsp`. Bạn sẽ thấy nó trong các hướng dẫn cũ.
</Callout>

Để liệt kê các client đang gắn vào buffer hiện tại, chạy `:lua =vim.lsp.get_clients({ bufnr = 0 })`.

## Phím tắt cho mã

| Phím | Tác dụng |
| --- | --- |
| `gd` / `gD` | đi đến định nghĩa / khai báo |
| `K` / `grn` | xem tài liệu (hover) / đổi tên |
| `grr` / `gri` | tham chiếu / phần triển khai |
| `gra` / `<leader>ca` | code action |
| `grt` / `gO` | định nghĩa kiểu / các symbol trong tệp |
| `grx` | chạy codelens |
| `<C-s>` | gợi ý chữ ký hàm (chế độ insert) |
| `<leader>cf` | định dạng buffer hoặc phần đang chọn |
| `<leader>cd` / `<leader>cl` | chẩn đoán của dòng / danh sách vị trí chẩn đoán |
| `]d` / `[d` | chẩn đoán kế tiếp / trước đó |

Chỉ `gd`, `gD` và `<leader>ca` đến từ các tệp bạn đã viết. Phần còn lại có sẵn trong Neovim: hầu hết từ 0.11, `grt` và `grx` từ 0.12. trouble.nvim (`<leader>xx`) cung cấp danh sách chẩn đoán; nó xuất hiện ở Phần 5.

## Thêm một ngôn ngữ của riêng bạn

Một ngôn ngữ mới chạm vào ba tệp, và Terraform đã được thiết lập đúng như vậy:

1. **Server và công cụ** trong `lua/config/plugins/lsp.lua`. Thêm tên server vào `lsp_servers`, và mọi trình định dạng hay linter vào `mason_tools()`. Chỉ thêm khối `vim.lsp.config` nếu server cần ghi đè.
2. **Trình định dạng** trong `lua/config/plugins/formatting.lua`. Thêm một dòng vào `formatters_by_ft`.
3. **Linter** trong `lua/config/plugins/linting.lua`. Thêm một dòng vào `linters_by_ft`.

Nếu Neovim đoán sai loại tệp, hãy thêm một ánh xạ giống như ở Bước 5. Nếu bạn cũng muốn tô màu cú pháp, hãy thêm parser Treesitter của ngôn ngữ đó vào `lua/config/plugins/treesitter.lua`. Đây là khuôn mẫu các tệp tuân theo, không phải lời khuyên từ tài liệu của các plugin, nên hãy xem tài liệu riêng của từng công cụ để biết chi tiết.

## Khắc phục sự cố

- **Server không gắn vào.** Chạy `:checkhealth vim.lsp`, rồi mở `:Mason` và kiểm tra server có hiện là đã cài không.
- **Lưu mà không định dạng.** Lỗi của trình định dạng được cố ý để im lặng. Chạy `:ConformInfo` để xem trình định dạng nào đã chạy và có gì sai.
- **Linter không làm gì.** Nó chỉ chạy khi đã được cài. Chạy `:MasonToolsInstall`, rồi lưu lại.
- **Tệp `.tf` mới có loại tệp `tf`.** Điều này xảy ra nếu bạn bỏ qua Bước 5, nơi ánh xạ phần mở rộng. Thêm các dòng đó, mở lại tệp, hoặc chạy `:set ft=terraform`.
- **Thiếu `sqlfluff`.** Python của bạn cũ hơn 3.10, nên cấu hình bỏ qua nó. Xem [Phần 1](/vi/blog/neovim-setup-1-zero-to-editor/).
