This guide takes you from nothing to a working Neovim on macOS by building a small config yourself, one file at a time. The config is meant for a mix of web, data engineering and SRE work: Java, Python, DBT/SQL, Terraform, Bash, CloudFormation/YAML, JSON, Docker and frontend files. It needs **Neovim 0.12 or newer**, and "Before you start" checks that.

I wrote it because big distros like LazyVim or NvChad do a lot for you, and then it's hard to tell which part does what. The config you build here is the opposite: one Lua file per topic, plugins loaded only when they're needed, and every line shown in this guide. Over five parts you'll build it up step by step. This first part creates the base: the core settings, the plugin manager and the first plugins. You can see the whole series on the [series page](/blog/series/neovim-setup-guide/).

<Callout type="note">
  **Tested with:** Neovim 0.12, macOS.
</Callout>

## What you'll have at the end

When you finish this part, you'll have:

- **lazy.nvim** as the plugin manager, with plugins that are lazy-loaded by default.
- **oil.nvim** as a file explorer that works like a normal buffer.
- **telescope.nvim** as a fuzzy finder for files, text and buffers.
- **smart-splits** and **flash** to move between splits and jump around a file.
- **Autopairs** and **surround** for editing, and **gitsigns** and **diffview** for Git.
- **Treesitter** syntax highlighting.
- A **lualine** statusline, **which-key** hints when you press a key prefix, the **catppuccin mocha** theme, and sessions with **persistence**.

Language servers, completion, formatting and linting arrive in Part 2.

A word on "lazy-loaded", since it explains most of how this config feels. A normal plugin loads every time Neovim starts, so each plugin adds to the startup time. A lazy-loaded plugin waits until you use it: pressing a mapped key, running a command or opening a certain kind of file. That's how a config with this many plugins can still start in a blink. The price is that a failing plugin might only show up when you first reach for it, which is why the checks in Step 7 matter.

## Before you start

You need macOS with [Homebrew](https://brew.sh). On Linux, install Neovim 0.12 or newer with your package manager (see the [Neovim install page](https://github.com/neovim/neovim/blob/master/INSTALL.md)). The Lua files work the same there, but the Homebrew commands in this guide are for macOS. On top of that:

- **Neovim 0.12 or newer.** Check what you have:

  ```sh
  $ nvim --version
  ```

  If it's older, or missing, run `brew install neovim` (or `brew upgrade neovim`).

<Callout type="warning">
  Neovim 0.11 and older fail on this config. It sets the 0.12-only `pumborder` option and loads
  the built-in undotree with `packadd nvim.undotree`.
</Callout>

- **A Nerd Font** set in your terminal, for example FiraCode Nerd Font:

  ```sh
  $ brew install --cask font-fira-code-nerd-font
  ```

  Without one, the icons show up as empty boxes.

- **Xcode Command Line Tools** (`xcode-select --install`). Telescope's `fzf-native` extension is built with `make`.
- **Python 3.10 or newer**, if you want Mason to install `sqlfluff`. Part 2 installs it only on Python 3.10+.

## Step 1: install the host tools

Neovim calls several programs on your machine. Install them with Homebrew and pipx:

```sh
$ brew install neovim git curl ripgrep fd tree-sitter-cli node python pipx openjdk terraform shellcheck shfmt tflint cfn-lint
$ pipx install dbt-core
$ pipx install sqlfluff
```

Here is why each one is there:

- `git` and `curl`: lazy.nvim clones plugins with git, and Mason downloads tools.
- `ripgrep` and `fd`: telescope uses them to search file contents and file names.
- `tree-sitter-cli`: the command-line tool that builds Treesitter parsers.
- `node`: many language servers are JavaScript programs, and `prettier` needs it too.
- `python` and `pipx`: `dbt-core` and `sqlfluff` live in their own isolated environments.
- `openjdk`: only needed for Java, which Part 4 covers.
- `terraform`, `shellcheck`, `shfmt`, `tflint` and `cfn-lint`: formatters and linters for Terraform, Bash and CloudFormation, used in Part 2.

Optionally, install `lazygit` for a Git interface. Part 5 maps it to <kbd>Space</kbd> <kbd>g</kbd> <kbd>g</kbd>:

```sh
$ brew install lazygit
```

If a command in this step fails, don't keep going. A missing tool now becomes a confusing error later, and fixing it takes a minute. Run `brew doctor` if Homebrew itself complains, and re-run the failed command once the problem is fixed. Homebrew skips anything that's already installed, so repeating the command is safe.

## Step 2: create the config folder

Neovim reads its config from one folder, and you put every file of this guide in it. All file paths in the guide are relative to that folder. Pick one of two ways to create it:

1. **A fresh setup.** The folder is `~/.config/nvim`. Back up anything you already have, then create the folders:

   ```sh
   $ mv ~/.config/nvim ~/.config/nvim.bak
   $ mv ~/.local/share/nvim ~/.local/share/nvim.bak
   $ mv ~/.local/state/nvim ~/.local/state/nvim.bak
   $ mv ~/.cache/nvim ~/.cache/nvim.bak
   $ mkdir -p ~/.config/nvim/lua/config/core ~/.config/nvim/lua/config/plugins
   ```

   If one of those folders doesn't exist, `mv` just says so. You can ignore that.

2. **Next to an existing config.** Neovim reads its config from a folder named after `NVIM_APPNAME`, so you can build this config next to your own. The folder is `~/.config/nvim-guide`:

   ```sh
   $ mkdir -p ~/.config/nvim-guide/lua/config/core ~/.config/nvim-guide/lua/config/plugins
   ```

   You start it with `NVIM_APPNAME=nvim-guide nvim`. Plugins and state then go to `nvim-guide` folders too, so your normal setup stays as it is.

<Callout type="tip">
  If you chose option 2, type `NVIM_APPNAME=nvim-guide nvim` wherever this guide says `nvim`, or
  add an alias such as `alias nvg='NVIM_APPNAME=nvim-guide nvim'`.
</Callout>

To check which folder Neovim reads, start it and run `:echo stdpath("config")`. It prints the folder you just created. You can write the files in any editor. For example, `nvim ~/.config/nvim/init.lua` opens a new file, and `:w` creates it.

You now have a folder of plain text files and nothing else. Nothing is hidden inside a plugin or a generated bundle, and that's the point: if you want to know why something behaves the way it does, you can open the file and read it.

## How the config fits together

Before you write the files, it helps to know what happens when Neovim starts, so each file has a place in your head.

<NeovimStartupDiagram lang="en" />

Neovim reads `init.lua`. It turns on `vim.loader`, which caches compiled Lua, and then loads two things: the core settings and lazy.nvim. The core settings set <kbd>Space</kbd> as the leader key, then load options, keymaps and autocmds. `lazy.lua` installs lazy.nvim if it isn't there yet, then hands over the plugin list. Every file in the `plugins/` folder is loaded for you, and each one covers one topic. Over the series you create these files:

| File | What it holds | Part |
| --- | --- | --- |
| `ui.lua` | theme, statusline, icons, which-key, sessions | 1 |
| `navigation.lua` | oil, telescope, smart-splits, flash | 1 |
| `editing.lua` | autopairs, surround, plenary | 1 |
| `git.lua` | gitsigns, diffview | 1 |
| `treesitter.lua` | Treesitter parsers | 1 |
| `lsp.lua` | mason, lspconfig, nvim-jdtls, lazydev | 2 |
| `completion.lua` | blink.cmp, snippets | 2 |
| `formatting.lua` | conform.nvim | 2 |
| `linting.lua` | nvim-lint | 2 |
| `data.lua` | DBT, database and YAML tools | 3 |
| `lua/config/java.lua` and `ftplugin/java.lua` | the Java launcher | 4 |
| `dev.lua` | trouble, grug-far, dap, neotest | 5 |
| `extras.lua` | quicker, treesitter-context, todo-comments, snacks, refactoring, overseer | 5 |

Paths in the table are relative to `lua/config/plugins/` unless they are shown in full.

## Step 3: init.lua and core settings

You create five files. None of them needs a plugin, so they all work on their own.

1. Create `init.lua` in the config folder. It is the first file Neovim reads. It loads the core settings and then lazy.nvim:

   ```lua title="init.lua"
   -- Minimal Neovim config for web, data, Java/Python, and SRE work.
   vim.loader.enable()

   require("config.core")
   require("config.lazy")
   ```

2. Create `lua/config/core/init.lua`. It sets <kbd>Space</kbd> as the leader key and turns off netrw, because oil.nvim is the file browser. The loop switches off the optional Node, Perl, Python and Ruby providers, which keeps `:checkhealth` quiet about them. The last three lines load the other core files:

   ```lua title="lua/config/core/init.lua"
   vim.g.mapleader = " "
   vim.g.maplocalleader = " "

   -- Disable netrw before plugins load. oil.nvim is the file browser.
   vim.g.loaded_netrw = 1
   vim.g.loaded_netrwPlugin = 1

   -- No remote plugins: silence the optional provider health checks
   for _, p in ipairs({ "node", "perl", "python3", "ruby" }) do
     vim.g["loaded_" .. p .. "_provider"] = 0
   end

   require("config.core.options")
   require("config.core.keymaps")
   require("config.core.autocmds")
   ```

3. Create `lua/config/core/options.lua`. These are the editor defaults: line numbers, two-space indentation, smart-case search, persistent undo and rounded borders. `winborder` and `pumborder` need Neovim 0.12. The clipboard option is set inside `vim.schedule` so it doesn't slow down startup:

   ```lua title="lua/config/core/options.lua"
   local opt = vim.opt

   opt.number = true
   opt.relativenumber = true
   opt.cursorline = true
   opt.signcolumn = "yes"
   opt.termguicolors = true
   opt.laststatus = 3
   opt.winborder = "rounded"
   opt.showmode = false

   opt.expandtab = true
   opt.shiftwidth = 2
   opt.tabstop = 2
   opt.softtabstop = -1
   opt.shiftround = true
   opt.wrap = false
   opt.linebreak = true
   opt.breakindent = true

   opt.ignorecase = true
   opt.smartcase = true
   opt.inccommand = "split"
   opt.splitbelow = true
   opt.splitright = true
   opt.splitkeep = "screen"
   opt.scrolloff = 8
   opt.sidescrolloff = 8

   vim.schedule(function()
     opt.clipboard = "unnamedplus"
   end)
   opt.undofile = true
   opt.confirm = true
   opt.updatetime = 250
   opt.timeoutlen = 400
   opt.completeopt = { "menu", "menuone", "noselect", "fuzzy" }
   opt.pumheight = 10
   opt.pumborder = "rounded"
   opt.mouse = "a"
   opt.smoothscroll = true
   opt.jumpoptions = "view"
   opt.virtualedit = "block"
   opt.foldlevelstart = 99
   opt.fillchars = { eob = " ", fold = " ", foldsep = " " }
   opt.sessionoptions = { "buffers", "curdir", "tabpages", "winsize", "help", "globals", "skiprtp" }

   opt.list = true
   opt.listchars = { tab = "» ", trail = "·", nbsp = "␣", extends = "›", precedes = "‹" }

   -- Built-in fallback; the real theme is catppuccin (plugins/ui.lua).
   pcall(vim.cmd.colorscheme, "habamax")
   ```

4. Create `lua/config/core/keymaps.lua`. These are the keymaps that don't need a plugin: save and quit with <kbd>Space</kbd> <kbd>w</kbd> and <kbd>Space</kbd> <kbd>q</kbd>, buffer switching, centered scrolling and search, and the built-in undo tree on `<leader>uu`:

   ```lua title="lua/config/core/keymaps.lua"
   local map = vim.keymap.set

   map("n", "<Esc>", "<cmd>nohlsearch<CR>", { desc = "Clear search highlight" })
   map("n", "<leader>w", "<cmd>write<CR>", { desc = "Save file" })
   map("n", "<leader>q", "<cmd>quit<CR>", { desc = "Quit window" })
   map("n", "<leader>bd", "<cmd>bdelete<CR>", { desc = "Close buffer" })

   map("n", "<leader>cd", vim.diagnostic.open_float, { desc = "Line diagnostics" })
   -- [d / ]d are built in (Neovim 0.11+); float-on-jump is set in vim.diagnostic.config.
   map("n", "<leader>cl", vim.diagnostic.setloclist, { desc = "Diagnostic loclist" })

   map("t", "<Esc><Esc>", "<C-\\><C-n>", { desc = "Exit terminal mode" })

   -- Window navigation is <M-h/j/k/l> via smart-splits.nvim (plugins/navigation.lua).

   -- Some terminals send ^A / ^E for Cmd+Left / Cmd+Right; keep them useful in insert mode.
   map("i", "<C-a>", "<C-o>^", { desc = "Start of line" })
   map("i", "<C-e>", "<End>", { desc = "End of line" })

   -- Editing quality-of-life
   map("x", "<", "<gv", { desc = "Outdent and keep selection" })
   map("x", ">", ">gv", { desc = "Indent and keep selection" })
   map("x", "J", ":m '>+1<CR>gv=gv", { desc = "Move selection down", silent = true })
   map("x", "K", ":m '<-2<CR>gv=gv", { desc = "Move selection up", silent = true })
   map("n", "<C-d>", "<C-d>zz", { desc = "Half page down (centered)" })
   map("n", "<C-u>", "<C-u>zz", { desc = "Half page up (centered)" })
   map("n", "n", "nzzzv", { desc = "Next match (centered)" })
   map("n", "N", "Nzzzv", { desc = "Prev match (centered)" })
   map("x", "<leader>p", [["_dP]], { desc = "Paste without clobbering register" })
   map("n", "<S-h>", "<cmd>bprevious<CR>", { desc = "Previous buffer" })
   map("n", "<S-l>", "<cmd>bnext<CR>", { desc = "Next buffer" })
   map("n", "<leader>bo", "<cmd>%bdelete|edit #|bdelete #<CR>", { desc = "Close other buffers" })
   map("n", "<leader>ur", "<cmd>nohlsearch|diffupdate|redraw!<CR>", { desc = "Redraw / clear highlights" })
   map("n", "<leader>uu", function()
     vim.cmd.packadd("nvim.undotree")
     vim.cmd.Undotree()
   end, { desc = "Undo tree (built-in)" })
   ```

5. Create `lua/config/core/autocmds.lua`. These are small quality-of-life autocommands in one group, `config_core`: highlight yanked text, wrap and spell-check prose files, restore the cursor position, reload files changed outside Neovim, keep splits equal after a resize, create missing parent folders on save, and close help-like buffers with <kbd>q</kbd>. Later parts add to this file:

   ```lua title="lua/config/core/autocmds.lua"
   local augroup = vim.api.nvim_create_augroup("config_core", { clear = true })

   vim.api.nvim_create_autocmd("TextYankPost", {
     group = augroup,
     callback = function()
       vim.hl.on_yank({ timeout = 180 })
     end,
   })

   vim.api.nvim_create_autocmd("FileType", {
     group = augroup,
     pattern = { "markdown", "text", "gitcommit" },
     callback = function()
       vim.opt_local.wrap = true
       vim.opt_local.spell = true
     end,
   })

   -- Restore the last cursor position when reopening a file.
   vim.api.nvim_create_autocmd("BufReadPost", {
     group = augroup,
     callback = function(ev)
       if vim.bo[ev.buf].buftype ~= "" or vim.bo[ev.buf].filetype:match("^git") then
         return
       end
       local mark = vim.api.nvim_buf_get_mark(ev.buf, '"')
       if mark[1] > 0 and mark[1] <= vim.api.nvim_buf_line_count(ev.buf) then
         pcall(vim.api.nvim_win_set_cursor, 0, mark)
       end
     end,
   })

   -- Reload files changed outside Neovim (git checkout, formatters, other panes).
   vim.api.nvim_create_autocmd({ "FocusGained", "TermClose", "TermLeave" }, {
     group = augroup,
     callback = function()
       if vim.o.buftype ~= "nofile" then
         vim.cmd("checktime")
       end
     end,
   })

   -- Keep splits equal when the terminal is resized.
   vim.api.nvim_create_autocmd("VimResized", {
     group = augroup,
     callback = function()
       local tab = vim.fn.tabpagenr()
       vim.cmd("tabdo wincmd =")
       vim.cmd("tabnext " .. tab)
     end,
   })

   -- Create missing parent directories on save.
   vim.api.nvim_create_autocmd("BufWritePre", {
     group = augroup,
     callback = function(ev)
       if ev.match:match("^%w%w+:[\\/][\\/]") then
         return
       end
       vim.fn.mkdir(vim.fn.fnamemodify(vim.uv.fs_realpath(ev.match) or ev.match, ":p:h"), "p")
     end,
   })

   -- Close throwaway buffers with just `q`.
   vim.api.nvim_create_autocmd("FileType", {
     group = augroup,
     pattern = { "help", "qf", "man", "checkhealth", "lspinfo", "notify" },
     callback = function(ev)
       vim.bo[ev.buf].buflisted = false
       vim.keymap.set("n", "q", "<cmd>close<CR>", { buffer = ev.buf, silent = true, desc = "Close window" })
     end,
   })
   ```

## Step 4: add lazy.nvim

1. Create `lua/config/lazy.lua`. The highlighted lines are the three parts that matter. The first block is the bootstrap: the first time, `git clone` fetches lazy.nvim into Neovim's data folder. The `import` line loads every file in `lua/config/plugins/`, so adding a plugin file is all it takes to add a plugin. `defaults = { lazy = true }` makes every plugin wait until something needs it, such as a key press, a command or a file type:

   ```lua title="lua/config/lazy.lua" {3-10,23,25}
   local lazypath = vim.fn.stdpath("data") .. "/lazy/lazy.nvim"
   if not vim.uv.fs_stat(lazypath) then
     local out = vim.fn.system({
       "git",
       "clone",
       "--filter=blob:none",
       "--branch=stable",
       "https://github.com/folke/lazy.nvim.git",
       lazypath,
     })
     if vim.v.shell_error ~= 0 then
       vim.api.nvim_echo({
         { "Failed to clone lazy.nvim:\n", "ErrorMsg" },
         { out, "WarningMsg" },
       }, true, {})
       os.exit(1)
     end
   end
   vim.opt.rtp:prepend(lazypath)

   require("lazy").setup({
     spec = {
       { import = "config.plugins" },
     },
     defaults = { lazy = true },
     checker = { enabled = false },
     change_detection = { enabled = false, notify = false },
     rocks = { enabled = false },
     performance = {
       rtp = {
         disabled_plugins = {
           "gzip",
           "tarPlugin",
           "tohtml",
           "tutor",
           "zipPlugin",
         },
       },
     },
     ui = { border = "rounded" },
   })
   ```

2. The rest of the file turns off things you don't need: the update checker, change detection, luarocks support and a few built-in plugins such as `tohtml` and `tutor`.

This bootstrap follows the [lazy.nvim installation page](https://lazy.folke.io/installation), which is the place to look if lazy.nvim changes how it installs.

## Step 5: add the first plugins

Create one file per topic in `lua/config/plugins/`. Each file returns a list of plugin specs, and lazy.nvim reads them all through the `import` line from Step 4. Nothing is installed until the first launch in Step 6.

### ui.lua

1. Create `lua/config/plugins/ui.lua`:

   ```lua title="lua/config/plugins/ui.lua"
   return {
     { "nvim-tree/nvim-web-devicons", lazy = true },

     {
       "catppuccin/nvim",
       name = "catppuccin",
       lazy = false,
       priority = 1000,
       opts = {
         flavour = "mocha",
         integrations = { which_key = true, gitsigns = true, treesitter = true },
       },
       config = function(_, opts)
         require("catppuccin").setup(opts)
         vim.cmd.colorscheme("catppuccin")
       end,
     },

     {
       "folke/persistence.nvim",
       event = "BufReadPre",
       opts = {},
       keys = {
         {
           "<leader>Ss",
           function()
             require("persistence").load()
           end,
           desc = "Restore session (cwd)",
         },
         {
           "<leader>Sl",
           function()
             require("persistence").load({ last = true })
           end,
           desc = "Restore last session",
         },
         {
           "<leader>Sd",
           function()
             require("persistence").stop()
           end,
           desc = "Don't save session",
         },
       },
     },

     {
       "nvim-lualine/lualine.nvim",
       event = "VeryLazy",
       dependencies = { "nvim-tree/nvim-web-devicons" },
       opts = function()
         local function lsp_clients()
           local names = {}
           for _, c in ipairs(vim.lsp.get_clients({ bufnr = 0 })) do
             names[#names + 1] = c.name
           end
           return #names > 0 and (" " .. table.concat(names, ", ")) or ""
         end

         return {
           options = {
             theme = "auto",
             globalstatus = true,
             component_separators = { left = "\u{e0b5}", right = "\u{e0b7}" },
             section_separators = { left = "\u{e0b4}", right = "\u{e0b6}" },
             disabled_filetypes = { statusline = { "dashboard", "alpha", "snacks_dashboard" } },
           },
           sections = {
             lualine_a = {
               { "mode", separator = { left = "\u{e0b6}" }, right_padding = 2 },
             },
             lualine_b = {
               { "branch", icon = "" },
               {
                 "diff",
                 symbols = { added = " ", modified = " ", removed = " " },
               },
             },
             lualine_c = {
               { "filetype", icon_only = true, separator = "", padding = { left = 1, right = 0 } },
               { "filename", path = 1, symbols = { modified = " ●", readonly = " ", unnamed = "[No Name]" } },
               {
                 "diagnostics",
                 symbols = { error = " ", warn = " ", info = " ", hint = "󰌵 " },
               },
             },
             lualine_x = {
               { lsp_clients, color = { gui = "italic" } },
               {
                 "encoding",
                 cond = function()
                   return vim.bo.fileencoding ~= "utf-8"
                 end,
               },
               { "fileformat", symbols = { unix = "", dos = "", mac = "" } },
             },
             lualine_y = { { "progress" } },
             lualine_z = {
               { "location", separator = { right = "\u{e0b4}" }, left_padding = 2 },
             },
           },
           inactive_sections = {
             lualine_c = { "filename" },
             lualine_x = { "location" },
           },
         }
       end,
     },

     {
       "folke/which-key.nvim",
       event = "VeryLazy",
       opts = {
         preset = "modern",
         delay = 0,
         triggers = {
           { "<leader>", mode = { "n", "v" } },
           { "<localleader>", mode = { "n", "v" } },
         },
         spec = {
           { "<leader>b", group = "buffer" },
           { "<leader>c", group = "code" },
           { "<leader>d", group = "data / db" },
           { "<leader>D", group = "debug" },
           { "<leader>t", group = "test" },
           { "<leader>x", group = "diagnostics" },
           { "<leader>o", group = "tasks" },
           { "<leader>s", group = "find and replace" },
           { "<leader>f", group = "find" },
           { "<leader>g", group = "git" },
           { "<leader>u", group = "ui" },
           { "<leader>W", proxy = "<C-w>", group = "window" },
           { "<leader>q", desc = "Quit window" },
           { "<leader>S", group = "session" },
           { "<leader>w", desc = "Save file" },
           { "<leader>bd", desc = "Close buffer" },
         },
       },
     },
   }
   ```

This file gives you the **catppuccin** theme in its mocha flavour. It loads first (`lazy = false`, `priority = 1000`) so the colors are there before anything draws. **persistence** saves your session, and <kbd>Space</kbd> <kbd>S</kbd> <kbd>s</kbd> restores it for the current folder. **lualine** is the statusline; it already has a slot that lists attached language servers, which stays empty until Part 2. **which-key** shows the keys after a prefix. Its `spec` table names groups such as debug and test for later parts, and they appear once those keys exist.

### navigation.lua

1. Create `lua/config/plugins/navigation.lua`:

   ```lua title="lua/config/plugins/navigation.lua"
   return {
     {
       "stevearc/oil.nvim",
       lazy = false,
       keys = {
         {
           "<leader>e",
   ```

### treesitter.lua

1. Create `lua/config/plugins/treesitter.lua`:

   ```lua title="lua/config/plugins/treesitter.lua"
   return {
     {
       "nvim-treesitter/nvim-treesitter",
       branch = "main",
       lazy = false,
       build = ":TSUpdate",
       config = function()
         local parsers = {
           "lua",
           "luadoc",
           "vim",
           "vimdoc",
           "bash",
           "python",
           "sql",
           "java",
           "javascript",
           "typescript",
           "tsx",
           "html",
           "css",
           "json",
           "yaml",
           "toml",
           "dockerfile",
           "terraform",
           "hcl",
           "markdown",
           "markdown_inline",
           "regex",
         }
         local function install_missing()
           local installed = require("nvim-treesitter").get_installed("parsers")
           local missing = vim.tbl_filter(function(p)
             return not vim.list_contains(installed, p)
           end, parsers)
           if #missing == 0 then
             return
           end
           if vim.fn.executable("tree-sitter") ~= 1 then
             vim.notify("Install tree-sitter CLI for parser install/update: brew install tree-sitter-cli", vim.log.levels.WARN)
             return
           end
           require("nvim-treesitter").install(missing)
         end
         vim.api.nvim_create_autocmd("User", { pattern = "VeryLazy", once = true, callback = install_missing })
         pcall(vim.treesitter.language.register, "sql", "sql.dbt")
         pcall(vim.treesitter.language.register, "yaml", "yaml.cloudformation")
         pcall(vim.treesitter.language.register, "terraform", "terraform-vars")

         local function start(buf)
           local ft = vim.bo[buf].filetype
           if ft == "" then
             return
           end
           local lang = vim.treesitter.language.get_lang(ft) or ft
           if pcall(vim.treesitter.start, buf, lang) then
             vim.bo[buf].indentexpr = "v:lua.require'nvim-treesitter'.indentexpr()"
           end
         end

         vim.api.nvim_create_autocmd("FileType", {
           group = vim.api.nvim_create_augroup("treesitter_start", { clear = true }),
           callback = function(args)
             start(args.buf)
           end,
         })
         for _, buf in ipairs(vim.api.nvim_list_bufs()) do
           if vim.api.nvim_buf_is_loaded(buf) then
             start(buf)
           end
         end
       end,
     },
   }
   ```

This file uses the `main` branch of nvim-treesitter, which needs the `tree-sitter-cli` tool from Step 1. After startup it installs any parser from the `parsers` list that is missing, and warns you if the CLI isn't there. The `start` function turns on Treesitter highlighting and indentation for every file type that has a parser. The three `language.register` lines map the `sql.dbt`, `yaml.cloudformation` and `terraform-vars` file types to existing parsers. Part 3 explains the first two.

## Step 6: first launch

1. Run `nvim`. The first start takes a while, because a lot happens in the background:

   - **lazy.nvim** installs the plugins. You'll see the `:Lazy` window. If anything fails, run `:Lazy sync` to try again.
   - **Treesitter** installs its parsers once Neovim has started. If the `tree-sitter` command is missing, you'll see this warning:

     ```text
     Install tree-sitter CLI for parser install/update: brew install tree-sitter-cli
     ```

2. Wait until nothing in `:Lazy` is marked as installing. Don't worry if the screen looks busy. Progress bars and messages appear and disappear while the plugins install, and a few lines of red text are common when a download is interrupted. Mason, which installs the language servers, arrives in Part 2.
3. Quit with `:q` and open Neovim once more. The second start should be quick and quiet, and the theme should be catppuccin.

The second launch is also a good moment to look at how fast it is. Run `nvim --startuptime startup.log` and open the log: most entries are tiny, because plugins that are not needed yet are not loaded. If your startup is slow, the log shows which file or plugin costs the most time.

## Step 7: check that everything works

1. Run `:checkhealth lazy` and `:checkhealth nvim-treesitter`. Both should end without errors. Warnings about optional providers, such as Ruby or Perl, are usually safe to ignore.
2. Open `init.lua`. Treesitter colours the Lua code.
3. Press <kbd>Space</kbd> and wait. which-key shows the groups of keymaps.
4. Press <kbd>Space</kbd> <kbd>f</kbd> <kbd>f</kbd>. Telescope opens with a list of files.
5. Press `-`. oil opens the folder of the current file.
6. Inside a Git repository, change a line in a tracked file. A sign appears in the left gutter.
7. Press <kbd>Space</kbd> <kbd>u</kbd> <kbd>u</kbd>. The built-in undo tree opens.

If all seven work, your host tools and your plugins are talking to each other correctly. Part 2 adds language servers, completion, formatting and linting.

## The first keymaps to learn

Press <kbd>Space</kbd> and wait: which-key shows every group of keymaps. Start with these:

| Key | Action |
| --- | --- |
| `<leader>ff` | find files |
| `<leader>fg` | live grep |
| `<leader>fb` | buffers |
| `<leader>e` | file explorer (float) |
| `-` | open the parent directory |
| `<leader>w` | save |
| `<leader>j` | jump to any visible text |
| `]d` / `[d` | next / previous diagnostic |
| `]h` / `[h` | next / previous git hunk |
| `<M-h/j/k/l>` | move between splits |
| `<leader>uu` | undo tree |

The keymaps follow a pattern that is easy to remember. After <kbd>Space</kbd>, the first letter picks a group: <kbd>f</kbd> for find, <kbd>g</kbd> for git, <kbd>c</kbd> for code, <kbd>b</kbd> for buffers and <kbd>u</kbd> for UI toggles. The second letter picks the action. When you forget one, press <kbd>Space</kbd> and read the list; that's what which-key is for.

`<leader>` is <kbd>Space</kbd>, and `<M-…>` is the Option key on macOS (your terminal must send it as Alt).

Most problems in this setup come down to one of three things: a missing host tool, a terminal that isn't configured for icons, or a download that was interrupted. When something looks wrong, start with `:checkhealth` and `:Lazy`, because they usually name the problem directly. The list below covers the ones I hit most often.

## Troubleshooting

- **Icons show as boxes.** Your terminal isn't using a Nerd Font. Set one in the terminal's font setting.
- **A warning about the `tree-sitter` CLI.** Run `brew install tree-sitter-cli`, then `:TSUpdate`.
- **Telescope is slow, or the fzf extension is missing.** Install the Xcode Command Line Tools, then run `:Lazy build telescope-fzf-native.nvim`.
- **You want to start over.** Remove `~/.local/share/nvim` (or `~/.local/share/nvim-guide`) and launch again.
